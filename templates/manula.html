Guía técnica: Actualizar Turnos App en GitHub + Render

1. Flujo de trabajo con Git

  • Editar tu código en Visual Studio Code (ejemplo: app.py, templates/*.html).
  • Guardar los cambios.
  • Ejecutar en la terminal: 
    git add .
git commit -m "Descripción del cambio"
git push
  • Esto sube el cambio a GitHub en la rama main.

2. Conexión GitHub ↔ Render

  • Render está vinculado a tu repo acasamassima197/turnos-app.
  • Cuando hacés git push, Render recibe la notificación automáticamente.
  • Render clona el repo, instala dependencias (pip install -r requirements.txt) y arranca con gunicorn app:app.
  • Si tu app.py incluye init_db(), se crea la tabla turnos al inicio.

3. Qué pasa en Render

  • El servicio entra en estado building → deploying → live.
  • La URL pública (ejemplo: https://turnos-app1.onrender.com) refleja los cambios.
  • En plan gratuito, la instancia se “duerme” si no hay actividad, y puede tardar ~50 segundos en despertar.

4. Pasos para verificar cambios

  1. Hacer un cambio mínimo (ejemplo: texto en index.html).
  2. Commit y push.
  3. Esperar unos segundos: Render redeploya solo.
  4. Entrar a la URL pública y comprobar el cambio.

5. Consideraciones sobre la base de datos

  • Actualmente usás SQLite (turnos.db), que se borra en cada redeploy.
  • Para persistencia real, deberías crear un servicio de PostgreSQL en Render y conectar Flask a esa base.

6. Resumen rápido

Editar → Commit → Push → Render redeploya → URL pública actualizada.
No hace falta tocar nada en Render salvo la primera configuración.
